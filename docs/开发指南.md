# 开发指南

> 配套《珍宝猎人》v8.1 方案（[方案全文](珍宝猎人-方案v8-MVP.md)）。这份文档只讲**代码怎么组织、改哪里、别踩什么坑**。

## 1. 环境与命令

```bash
npm install          # Node ≥ 22
npm run dev          # Vite dev server，http://127.0.0.1:5173
npm run typecheck    # tsc --noEmit（含 tests）
npm run test         # Vitest（happy-dom），10 files / 57 tests
npm run build        # typecheck + vite build → dist/
npm run verify       # 以上三件套，提交前跑
```

产物是纯静态站：`dist/` 直接丢任意静态托管即可，`vite.config.ts` 里 `base: './'` 保证相对路径。**不要**为了"跑起来"引后端——两个 AI 都由浏览器直连（CORS 已实测）。

## 2. 五个概念，记住就不会写乱

| 概念 | 代码位置 | 一句话 |
|---|---|---|
| `LevelJson` | `src/types/level.ts` | 一关的**权威数据**：世界、创作人、5 件珍宝、价格。生成后基本只读 |
| `LevelSession` | `src/game/level.ts` | 一局的**唯一可变状态**：额度、报价、购买、精灵问答。UI 只通过它改状态 |
| `AppState` | `src/app/store.ts` | UI 视图状态（当前屏、busy、提示、模型 blob）。`store.set()` 会触发整屏重绘 |
| 纯函数内核 | `validate` / `economy` / `bargain` / `fairy` | 不碰 DOM、不碰 store、可完全单测 |
| 适配层 | `src/api/*` | 只做 HTTP 与契约解析；游戏逻辑只依赖 `ChatClient` 接口，方便 mock |

数据流：`actions.ts` 编排（生成 → 缓存 → 建 session → 改 store）→ `router.ts` 重绘 → 屏幕读 `session.state` 渲染。

## 3. 关卡协议与不变量

```ts
TreasureItem {
  name, pitch,
  traits:    真实可见特征（程序由 signatureTraits + tamperOps 推导）
  tamperOps: 混淆算子数组；[] ⇔ 真品
  isAuthentic: 程序覆写，LLM 说什么都不算
}
```

- **归一化入口**：`normalizeLevel(raw, {difficulty, funds, seedId, seedGenre, priceIndexRange, rng})`
  - Zod 校验失败 → 抛 `LevelSchemaError(issues)`，生成层把 issues 拼成"定向重试"提示。
  - 价格：`rebalancePrices` 强制 Σ ∈ [1.5, 2.2]×资金、单件 ≤ 0.9×资金、底价 ∈ [55%, 75%]。
  - 真伪：按难度目标真品数（3/2/1）增删仿品；仿品算子按难度整形（L1 两枚显性 / L2 一枚中等 / L3+ ±1）。
  - `trueValue` clamp 到创作人 `quoteRange`（普世锚，不乘物价指数）。
- **改数值**：只改 `src/config/constants.ts`（额度、回收、价格区间、算子白名单、色/形白名单）；不要在业务代码里写魔法数。
- **改 prompt**：只改 `src/config/prompts.ts`。`renderPromptForTraits` 与判定共用 traits，改模板时保持"特征 ↔ 模型"一一对应。

## 4. 各模块职责与扩展点

### 世界种子（`game/seeds.ts`）
30 条 `{id, genre, priceIndexRange, mood}`。新增世界只需追加一条；`priceIndexRange` 会作为硬约束传给 LLM 并在归一化时 clamp。

### 生成（`game/generation.ts`）
- `generateLevel`：DeepSeek `jsonChat`（JSON mode）→ 归一化；最多 3 次，第 2/3 次把上次的 issues 回灌。
- `ensureLevelModels`：**并发**拉 5 件 GLB（免费档并发 5），先查 IndexedDB，成功即写回；单件失败只记录 `errors[itemId]`，不拖垮整关。
- 想加"重掷关卡"？复用 `startGeneratedLevel()`，它会先 `pickSeed` 再走完整流程。

### 精灵（`game/fairy.ts`）
- `buildFairyContext(level)` **只能**取 world / creators 公开字段 / `collectTamperTypes`；**永远不要**把 `level.stalls` 传进去。
- `sanitizeQuestion`：≤50 码点；`filterAnswer`：压单行、截 100 字、命中"第X件 / T2 / 编号"整段替换为挡回语。
- 加人设：改 `FAIRY_PERSONA_POOL` 与 prompt 里的语气要求；**不要**为了"更聪明"把单件信息塞进去。

### 砍价（`game/bargain.ts`）
- `checkOffer`：结构闸门（已购 / 回合 / 额度 / 资金 / 非法报价）。
- 硬规则：`offer < bottomPrice` 必拒，**不问 LLM**。
- 混合模式：LLM 只输出 `{accept, line}`；失败退回 `localDecision`；兜底"接受价 ≥ 上次拒绝价"。
- 快速模式：设置页开关 → 全程 `localDecision`，零调用。
- 想调手感：改 `localThreshold` 的耐心系数（`0.05/回合`）与 `flexibility` 权重，注意保持 `bottom ≤ threshold ≤ salePrice`。

### 经济（`game/economy.ts`）
- 等级/额度：`levelForXp`、`offerQuota`、`fairyQuota`。
- 结算：`settleLevel(runtime, player, level, plan)`；`plan` 逐件 `{itemId, recycle}`，默认回收已购件。
- 结束：`checkMarketEnd` 顺序为 额度 → 资金低于最低底价 → 无可议之货；`actions.submitOffer` 在判定后自动收摊。

### 3D（`render/viewer.ts`）
- `new TreasureViewer(container)` → `show(blob | null, traits)`。
- 有 blob 走 `GLTFLoader.parse`；否则按 traits 生成占位模型（形制几何 + 颗数小球 + 底座）。
- 离开验货屏必须 `dispose()`：`screens/inspect.ts` 的 `disposeInspectViewer` 由 router 调用，避免 WebGL 上下文泄漏。
- 性能：GLB 13MB/件，一次只加载当前件；`viewer` 是当前唯一大头（three 让主包 ~819KB），后续可动态 import。

### 缓存（`store/cache.ts`）
- `gameCache.saveLevel / getLevel / saveModel / getModel / deleteLevel`。
- IndexedDB 不可用（隐私模式）自动退内存，本局仍可玩。
- 玩家存档走 localStorage（`gemwright.profile.v1`）；**运行时进度目前不持久化**（刷新会丢当前关，关卡与 GLB 仍在缓存里）。

### 设置（`store/settings.ts`）
- 只存 `deepseekKey / lux3dKey / region / quickBargain / acknowledgedCreditCost`。
- 展示用 `maskKey`；不要新增"导出/上传 Key"的能力。

## 5. UI 约定

- 屏幕是**纯函数**：`renderXxx(state) → HTMLElement`；store 变化整屏重绘。
- 局部状态（输入框内容、滑条、对勾）藏在 DOM 里，动作触发时才读值；**不要**为了每个按键都 `store.set`（会丢焦点）。
- 新加按钮：`button(label, {variant, onClick, disabled})`；新加区块：`section(title, ...children)`；提示：`noticeBar(state.notice, dismissNotice)`。
- 样式分层：`tokens.css`（颜色/间距）→ `base.css`（reset/按钮/表单）→ `components.css`（顶栏/徽章/表格）→ `screens.css`（具体屏幕）。优先用 token，不要硬编码颜色。
- 重绘会销毁屏幕：需要跨重绘的只有 `store`；需要清理的资源（WebGL、定时器）必须注册清理路径。

## 6. 测试策略

- 纯逻辑先测：`validate`（价格/真伪/难度）、`economy`（结算数学）、`bargain`（闸门/兜底）、`fairy`（防火墙/过滤）、适配层（请求头/状态码/重试）。
- 生成层用假 `ChatClient`：第一次喂坏 JSON，断言第二次带上了 issues。
- UI 冒烟用 happy-dom 渲染五个屏；`tests/boot.test.ts` 真跑 `src/main.ts`，兜住循环依赖 / 首屏白屏。
- 新增玩法优先级：**先写不变量测试，再接 UI**。例如新增算子类型，先在 `tamperPolicy` / `applyTamperOps` 加测试。
- 端到端（本机 Chrome + Playwright 驱动，非仓库依赖）：设置 → 演示关卡 → 集市 → 验货 → 出价 → 结算，截图存 `docs/screenshots/`。

## 7. 调试技巧

- DEV 模式浏览器控制台有 `window.gemwright`：
  ```js
  gemwright.store.get()              // 当前完整状态
  gemwright.store.get().session.state // 额度 / 报价 / 购买
  gemwright.actions.forceSeed(gemwright.store.get().nextSeed) // 固定当前种子
  ```
- 无 Key 想看 UI：任何页面「设置 → 去穿越 → 演示关卡」。
- 卡在"集市布展"：看 Console 是否有 CORS / 401 / 积分不足；Lux3D 的 `Authorization` 不能加 `Bearer`。
- 余额：DeepSeek 设置页「测试 Key」调 `/user/balance`；Lux3D 暂无余额接口，积分页自查。

## 8. 已知缺口（按优先级）

1. 真实 Key 未端到端联调（D1 验收项）；`ensureLevelModels` 的真实耗时 / 失败率待实测。
2. 运行时进度未持久化：刷新丢当前关，需把 `LevelRuntime` 序列化进 IndexedDB。
3. 3D 计数保真度未用真实 GLB 核验：先用 `outputs/样件/crystal_test.glb` 人眼对照，不稳就加重色族/形制权重。
4. 演出缺失：穿越过场、开箱雾、逐件揭晓、精灵打字机、摊主反应动画。
5. 工程化：无 ESLint/Prettier；three 未拆包（动态 import `viewer`）；无 CI。
6. 移动端未适配（方案明确不做，但触控滑条与 3D 手势已可用）。

## 9. 提交与协作

- 分支：`main` 直推（黑客松节奏）；一次提交聚焦一件事。
- 提交信息：`feat: ...` / `fix: ...` / `docs: ...`，中文描述即可。
- 提交前：`npm run verify`；涉及 UI 改动附一张 `docs/screenshots/` 更新截图。
- 不要提交：`.env`、真实 Key、`.verify/`、`.npm-cache/`、`dist/`。
