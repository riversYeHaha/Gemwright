# 开发指南

> 配套《珍宝猎人》v8.1 方案（[方案全文](珍宝猎人-方案v8-MVP.md)）。这份文档只讲**代码怎么组织、改哪里、别踩什么坑**。

## 1. 环境与命令

```bash
npm install          # Node ≥ 22
npm run dev          # Vite dev server，http://127.0.0.1:5173
npm run typecheck    # tsc --noEmit（含 tests）
npm run lint         # ESLint flat config
npm run format       # Prettier 写回 src / tests / 配置
npm run test         # Vitest（happy-dom），23 files / 104 tests
npm run build        # typecheck + vite build → dist/
npm run verify       # typecheck + lint + format:check + test + build，提交前跑
npm run models       # 生成教学/演示预置 GLB（需 Lux3D Key）
npm run models:dry   # 只打印预置模型的 prompt / 输出路径
npm run fairy        # Lux3D：文生 3D → 绑骨 → 6 动作（约 41 积分）
npm run fairy:dry    # 只打印精灵 prompt / 动作 / 预计积分
```

产物是纯静态站：`dist/` 直接丢任意静态托管即可，`vite.config.ts` 里 `base: './'` 保证相对路径。**不要**为了"跑起来"引后端——两个 AI 默认由浏览器直连；Lux3D 预检放行，但错误响应没有 CORS 头，必须用有效 Key / 正确地区，直连失败时先 curl，不要误以为是部署问题。

## 2. 八个概念，记住就不会写乱

| 概念 | 代码位置 | 一句话 |
|---|---|---|
| `LevelJson` | `src/types/level.ts` | 一关的**权威数据**：世界、创作人、珍宝、价格。`kind` 区分 generated / demo / tutorial |
| `LevelSession` | `src/game/level.ts` | 一局的**唯一可变状态**：额度、报价、购买、精灵问答；`fromRuntime` 可恢复快照 |
| `AppState` | `src/app/store.ts` | UI 视图状态（当前屏、busy、提示、模型 blob、续玩/教学标记）。`store.set()` 触发整屏重绘 |
| 纯函数内核 | `validate` / `economy` / `bargain` / `fairy` | 不碰 DOM、不碰 store、可完全单测 |
| 适配层 | `src/api/*` | 只做 HTTP 与契约解析；游戏逻辑只依赖 `ChatClient` 接口 |
| **开始画面** | `src/render/startBackdrop.ts`、`src/ui/screens/start.ts` | 无顶栏；canvas 黑洞背景 + 新游戏 / 继续 / 设置 / 说明四项菜单 |
| **陪伴精灵** | `src/ui/fairyCompanion.ts`、`src/ui/fairyChat.ts`、`src/render/fairyRig.mjs` | 右下角常驻；双击当前页弹出对话浮窗；状态 → 六套骨骼动画；Worker 渲染 |
| **教学沙盒** | `src/game/tutorial/level.ts` | 预置两件珍宝 + 剧本问答 + 六步目标；不调模型、不写存档 |
| **预置模型** | `scripts/init_models.py`、`src/store/localModels.ts` | 脚本用玩家 Key 生成 GLB 到 `public/models/`（不入库）；网页按 manifest 加载，缺失回退占位 |

数据流：`actions.ts` 编排（生成 → 缓存 → 建 session → 改 store）→ `router.ts` 重绘 → 屏幕读 `session.state` 渲染。

## 3. 关卡协议与不变量

```ts
TreasureItem {
  name, pitch,
  traits:    真实可见特征（程序由 signatureTraits + tamperOps 推导）
  tamperOps: 混淆算子数组；[] ⇔ 真品
  isAuthentic: 程序覆写，LLM 说什么都不算
}
```

- **归一化入口**：`normalizeLevel(raw, {difficulty, funds, seedId, seedGenre, priceIndexRange, rng})`
  - Zod 校验失败 → 抛 `LevelSchemaError(issues)`，生成层把 issues 拼成"定向重试"提示。
  - 价格：`rebalancePrices` 强制 Σ ∈ [1.5, 2.2]×资金、单件 ≤ 0.9×资金、底价 ∈ [55%, 75%]。
  - 真伪：按难度目标真品数（3/2/1）增删仿品；仿品算子按难度整形（L1 两枚显性 / L2 一枚中等 / L3+ ±1）。
  - `trueValue` clamp 到创作人 `quoteRange`（普世锚，不乘物价指数）。
- **改数值**：只改 `src/config/constants.ts`；**改 prompt**：只改 `src/config/prompts.ts`。
- `renderPromptForTraits(traits)` 与判定共用 traits，改模板时保持"特征 ↔ 模型"一一对应。

## 4. 各模块职责与扩展点

### 世界种子（`game/seeds.ts`）
30 条 `{id, genre, priceIndexRange, mood}`。新增世界只需追加一条；`priceIndexRange` 会作为硬约束传给 LLM 并在归一化时 clamp。

### 生成（`game/generation.ts`）
- `generateLevel`：DeepSeek `jsonChat`（JSON mode）→ 归一化；最多 3 次，第 2/3 次把上次的 issues 回灌。
- `ensureLevelModels`：**并发**拉 5 件 GLB（免费档并发 5），先查 IndexedDB，成功即写回；单件失败只记录 `errors[itemId]`，不拖垮整关。
- 单件失败会自动重试 1 次，仅限 `Lux3DError.code` 为 `task-failed` / `timeout` 或网络类错误；鉴权、参数、积分不足不重试。
- `hooks.signal`（AbortSignal）贯穿 create / poll / download；取消后该件标记 `skipped`，不产生 error。

### 精灵（`game/fairy.ts`）
- `buildFairyContext(level)` **只能**取 world / creators 公开字段 / `collectTamperTypes`；**永远不要**把 `level.stalls` 传进去。
- `sanitizeQuestion`：≤50 码点；`filterAnswer`：压单行、截 100 字、命中"第X件 / T2 / 编号"整段替换为挡回语。
- UI 侧 `typewrite()` 做打字机；节点离屏（整屏重绘）后自动停表。

### 砍价（`game/bargain.ts`）
- `checkOffer`：结构闸门（已购 / 回合 / 额度 / 资金 / 非法报价）。
- 硬规则：`offer < bottomPrice` 必拒，**不问 LLM**。
- 混合模式：LLM 只输出 `{accept, line}`；失败退回 `localDecision`；兜底"接受价 ≥ 上次拒绝价"。
- 快速模式：设置页开关 → 全程 `localDecision`，零调用；教学关与演示关强制本地判定。

### 经济（`game/economy.ts`）
- 等级/额度：`levelForXp`、`offerQuota`、`fairyQuota`。
- 结算：`settleLevel(runtime, player, level, plan)`；`plan` 逐件 `{itemId, recycle}`，默认回收已购件。
- 结束：`checkMarketEnd` 顺序为 额度 → 资金低于最低底价 → 无可议之货；`actions.submitOffer` 在判定后自动收摊。

### 3D（`render/viewer.ts`）
- `new TreasureViewer(container)` → `show(blob | null, traits)`；有 blob 走 `GLTFLoader.parse`，否则按 traits 生成占位模型。
- 占位模型的星砂使用 `depthTest: false` + `renderOrder`，保证**所有颗数都可见可数**（教学关 7 vs 6 的判定基础）。
- 该模块由 `screens/inspect.ts` **动态 import**（独立 chunk）；离开验货屏由 `disposeInspectViewer()` 释放 WebGL，路由在每次重绘前调用。
- 异步加载用 `viewerToken` 防止快速切换时的竞态；`viewer-fog` 负责开箱雾，1.6s 后移除。

### 开始画面缩略图（`render/modelSprites.ts` + `render/modelThumb.worker.ts`）
- 有 `public/models/manifest.json` 时，开始画面优先用真实 GLB：`collectModelEntries()` 按「教学 → 演示」排序，逐件加载，用 Worker 里的 three + GLTFLoader + OffscreenCanvas 拍成 320×320 缩略图。
- 主线程只负责下载 GLB、合成色族光晕、把缩略图交给 `startBackdrop`；**three 的解析 / WebGL 初始化 / 渲染全部在 Worker**，所以 10MB 级模型不会卡住黑洞动画（实测主线程最长任务从 ~2.5s 降到 ~200ms）。
- 渐进替换：`onSprite(sprite, slot)` 按 0..n 填充槽位，`startBackdrop` 用 0.7s 把对应槽位从程序化图形淡入真实模型；加载失败 / 无模型 / 省流量 / 2G / 无 `OffscreenCanvas` 的浏览器保留兜底图形。
- 缓存：缩略图按 `manifest.generatedAt + levelId + itemId` 存内存，回到开始页不重新解析；重新生成模型（新 generatedAt）会自然失效。
- 取消：开始页卸载 → `AbortController.abort()` → 停止后续 GLB 下载并 `worker.terminate()`；已下载的 blob 不会写入 `null` 缓存。
- 预算：桌面最多 7 件（与 7 个精灵槽位、manifest 的 7 件模型对齐），手机 4 件；不足的槽位 / 加载失败的槽位保留兜底图形；`navigator.connection.saveData` / 2G 直接跳过。
- 改模型展示：调整 `modelThumb.worker.ts` 的相机距离 / 灯光 / `group.rotation`；调色族光晕改 `modelSprites.ts` 的 `GLOW_RGB`。

### 缓存与续玩（`store/cache.ts`）
- `gameCache.saveLevel / getLevel / saveModel / getModel / deleteLevel`。
- IndexedDB 不可用（隐私模式）自动退内存，本局仍可玩。
- `saveActiveRun / loadActiveRun / clearActiveRun`：localStorage 存整个运行时快照（关卡 JSON + `LevelRuntime` + 玩家），刷新续玩。
- 教学关**不写**快照（`persistActiveRun` 显式跳过）；退出教学时恢复教学前的玩家存档。
- 玩家存档 `gemwright.profile.v1`；教学关结算不写玩家存档（沙盒隔离）。

### 设置（`store/settings.ts`）
- 只存 `deepseekKey / lux3dKey / region / quickBargain / acknowledgedCreditCost`。
- 展示用 `maskKey`；不要新增"导出/上传 Key"的能力。

## 5. 预置 3D 模型（P0）

- **模型不入库**：`public/models/` 在 `.gitignore`；仓库只提交脚本与提示词。
- 脚本：`scripts/init_models.py`（Python 3.9+，仅标准库）。内置教学 2 件 + 演示 5 件的 traits，prompt 与 `src/config/prompts.ts` 的 `renderPromptForTraits` 保持一致。
- 用法：
  ```bash
  npm run models:dry                         # 预览
  export LUX3D_API_KEY=...
  npm run models                             # 默认国内端点，7 件 ≈ 91 积分
  python3 scripts/init_models.py --region global --force
  ```
- 输出：`public/models/{tutorial,demo}/*.glb` + `public/models/manifest.json`（`levels[levelId][itemId]` 存相对路径）。
- 加载：`store/localModels.ts` 用 `document.baseURI` 解析 manifest 与 GLB；内存缓存；manifest 缺失 / 404 / 解析失败一律返回 null。
- 回退：`actions.resolveModelsForLevel()` 先取 IndexedDB（正式关），再合并预置模型（教学 / 演示）；`null` 由 viewer 用 traits 占位模型。
- 加一件预置模型：在脚本的 `TUTORIAL_ITEMS` / `DEMO_ITEMS` 加 `PresetItem`，traits 与关卡数据保持一致，再跑 `npm run models -- --force`（或 `python3 ... --force`）。
- 校验：脚本 `--dry-run` 输出 JSON；真实生成需要 Key，生成后用浏览器看验货页底部是否标注「本地预置模型」。
- 成本：13 积分/件；已存在默认跳过，可反复执行；Key 只放请求头，不落盘、不打印。

## 6. 开始画面与教学关卡

### 开始画面（`render/startBackdrop.ts` + `ui/screens/start.ts`）
- 路由对 `start` 屏**不渲染顶栏**；`start.ts` 只负责标题、菜单、状态行，背景全部交给 canvas。
- `mountStartBackdrop(host)`：固定全屏 canvas（窗口尺寸 × dpr≤2）。黑洞锚点桌面 `0.665w / 0.46h`，竖屏 `0.5w / 0.27h`（下方留给标题和菜单）。`renderStart()` 挂载时调用。
- 路由每次重绘前调用 `disposeStartBackdrop()`：取消 rAF、移除 `resize` / `visibilitychange`、清空 items / pool / flashes / stars / dust / sprites、断开离屏 canvas、移除节点。**新增全局监听必须在 dispose 里摘掉**。
- 珍宝从四周生成，轨迹用 `age / duration` 参数化（`t^2.6` 前慢后快），自转由 `spinSpeed + sin()` 抖动；接近视界时径向拉伸、切向压扁并淡出；`age >= duration` 立即从场景数组移除并回收到 `pool`（上限 36），不会无限增长。
- 性能：星空、黑洞、7 种兜底珍宝精灵全部预渲染；每帧只做 `drawImage` + 少量 `fillRect`；`document.hidden` 时暂停 rAF；`prefers-reduced-motion` 只画一帧静态画面。
- 无 2D context（测试 / 极端浏览器）时保留占位 canvas 并安静降级，`dispose` 仍会移除它。
- 新增菜单项：改 `start.ts` 的 `menuItem()`；顺序/文案变了要同步 `tests/start.test.ts` 的 `data-action` 断言。

### 子页面（`newgame` / `guide`）
- 主菜单固定四项：新游戏 → `newgame`、继续游戏（无快照时 disabled）→ `continueRun()`、设置 → `settings`、游戏说明 → `guide`。
- `ui/screens/newgame.ts`：教学 / 正式 / 演示三种开局；有续玩快照时提示「正式、演示会覆盖，教学不会」。
- `ui/screens/guide.ts`：玩法循环、四特征判定、精灵知道/不知道、额度与操作；纯静态，不读 session。
- 两页都走普通顶栏（`topbar()`），返回开始画面用 `navigate('start')`，不要用 `goStart()`（会多做一次存档恢复）。

### 教学关卡（`game/tutorial/level.ts`）
- `createTutorialLevel()` 手写世界 / 创作人 / 两件珍宝：真品 7 颗、仿品 6 颗，价格 380 / 350，能在 1000 资金内全买下且结算小赚。
- `TUTORIAL_QA`：5 条预设问答，其中 `which` 是**故意越界**的问题，返回 `BLOCKED_ANSWER`，用来演示防火墙。
- `tutorialObjectives({progress, askUsed, purchasedCount, phase, settled})`：六步全部由运行时状态推导，UI 用 `ui/tutorial.ts` 渲染；**不要**另埋事件。
- `tutorialObjectives` 依赖 `AppState.tutorial`：`{inspected: string[], openedMarket: boolean}`。`openInspect` / `beginShopping` 时更新。
- 教学关的 `persistActiveRun` / `persistPlayer` 都是 no-op；`startTutorial` 记录 `playerBeforeTutorial`，`goStart` / `nextLevel` 时恢复。
- 新增教学步骤：先在 `tutorialObjectives` 加目标，再在对应 action 里更新状态，最后补一条测试。

### 陪伴精灵（`scripts/init_fairy.py`、`render/fairyRig.mjs`、`fairyStage.worker.ts`、`ui/fairyCompanion.ts`）
- **主路径（Lux3D）**：`scripts/init_fairy.py` 依次调用 `text-to-3d/task/create` → `animations/rig/task/create` → `animations/retarget/task/create`（`animationOutputMode=combined`），下载最终 GLB 到 `public/models/fairy/fairy.glb` + `manifest.json`。约 20 + 15 + 6 = 41 积分；默认国内根地址 `https://api.aholo.cn`，可用 `--base-url` 覆盖。
- 脚本会校验最终 GLB 的 `skins` / `AnimationClip`，把实际 clip 名写进 `manifest.actions`（如 `idle → Idle_Loop`）；前端不写死 Lux3D 的动画名。
- **兜底路径**：没有 Key / 生成失败 / 旧产物不存在时，`fairyRig.mjs` 在 Worker 里实时构建 12 根程序化骨骼 + 6 套 clip；它与 Lux3D 产物共用同一套 action key，所以动作匹配逻辑不变。
- 成本与失败：任何一步失败都不会覆盖旧 `fairy.glb` / manifest；网页继续用上一个产物或程序化兜底。
- 渲染：`fairyCompanion.ts` 是挂在 `document.body` 的单例，不随 router 整屏重绘重建；首次进游戏 650ms 后动态 import `fairyStage.ts`，把 canvas 的 `transferControlToOffscreen()` 交给 `fairyStage.worker.ts`。three / WebGL / GLTFLoader / AnimationMixer 全在 Worker，主线程只发 `action` / `pause` / `resize`（实测长任务从 ~2.4s 降到 ~220ms）。
- 动作：`fairyTalk.fairyReaction(prev, next)` 是纯函数，优先级为 **新回答 > 成交 > notice > busy > 换世界 > 收摊 > 额度耗尽**；`fairyCompanion` 负责把它翻译成 `stage.play(action)`。动作与台词都有单测。
- 常驻：只在 `travel / market / inspect / base` 显示；`start / newgame / guide / settings` 隐藏。`body.has-fairy` 给 `.app` 加底部留白，避免遮住最后一张卡片。
- 交互：**单击**常驻精灵说一句自言语，**双击**（两次 click 间隔 <280ms）在任意游戏屏 `toggleFairyPanel(true)`；不再在 HUD 放「唤出/收起精灵」按钮。
- 对话浮窗：`ui/fairyChat.ts` 把 `<section class="fairy-chat">` 挂到 `document.body`，CSS `position: fixed`，不参与 `market-layout`，不会把集市挤成两栏。集市 / 教学关显示限次问答、打字机回答；其它游戏屏显示本地闲聊（不消耗额度，也不读真伪 / 价格）。浮窗头部「关闭」和 Esc 都能收起。
- 浮窗打开时常驻精灵只保留待机形象，不弹自言语气泡；关闭后恢复自言语。
- 自言自语：12–24 秒一次，6 秒消失；`fairyTalk.selfTalkLine()` 从静态池里按 persona / 教学关 / 额度 / 资金 / 世界挑一句。**不调用 LLM，不读 stalls / 价格 / 真伪**，防火墙不受影响。
- 降级：Lux3D GLB 加载失败 / 没有 GLB → `buildFairyRig()` 实时构建；没有 `OffscreenCanvas` / Worker 或舞台创建失败 → CSS 光球 + 台词气泡；`prefers-reduced-motion` 由主线程检测后传给 Worker，Worker 只画静态帧。
- 动作命名：Lux3D 用 `Idle_Loop / Idle_Talking_Loop / Idle_FoldArms_Loop / Dance_Loop / Crouch_Idle_Loop / Yes`；程序化兜底用 `Idle / Talk / Think / Happy / Sad / Alert`，两者都由 manifest / `FAIRY_ACTIONS` 映射到同一组动作 key。
- 改动作：在 `FairyAction` / `FAIRY_ACTIONS` 加键 → 更新 `init_fairy.py` 的 `ACTION_ANIMATIONS` → 兜底 `fairyRig.mjs` 加 clip → `fairyReaction` 映射 → 补测试；改台词只改 `ui/fairyTalk.ts`。

## 7. UI 约定

- 屏幕是**纯函数**：`renderXxx(state) → HTMLElement`；store 变化整屏重绘。
- 局部状态（输入框、滑条、对勾）藏在 DOM 里，动作触发时才读值；**不要**为每个按键 `store.set`（会丢焦点）。
- 新加按钮：`button(label, {variant, onClick, disabled})`；区块：`section(title, ...children)`；提示：`noticeBar(state.notice, dismissNotice)`；教学引导：`tutorialCoach(state)`。
- 样式分层：`tokens.css` → `base.css` → `components.css` → `screens.css` → `start.css`（开始画面）→ `fairy.css`（常驻精灵）。优先用 token，不要硬编码颜色。
- 重绘会销毁屏幕：需要清理的资源（WebGL、定时器）必须注册清理路径；打字机与 3D 加载都做了离屏/令牌保护。
- 开始画面的黑洞动画在 `prefers-reduced-motion` 下只渲染一帧（canvas 层面停表，不是简单关 CSS 动画）。
- 右下角精灵也尊重 `prefers-reduced-motion`：Worker 不启动渲染循环，只画静态帧。

## 8. 测试策略

- 纯逻辑先测：`validate`（价格/真伪/难度）、`economy`（结算数学）、`bargain`（闸门/兜底）、`fairy`（防火墙/过滤）、适配层（请求头/状态码/重试）。

## 9. 调试技巧

- DEV 模式浏览器控制台有 `window.gemwright`：
  ```js
  gemwright.store.get()               // 当前完整状态
  gemwright.store.get().session.state // 额度 / 报价 / 购买 / 阶段
  gemwright.actions.forceSeed(gemwright.store.get().nextSeed) // 固定当前种子
  gemwright.actions.startTutorial()   // 直接进教学
  ```
- 无 Key 想看 UI：开始画面 → 新游戏 → 教学关卡 / 演示关卡。
- 右下角没有精灵：确认进入了游戏屏（开始页 / 设置页本来就不显示）。看 Network 是否有 `models/fairy/manifest.json`、`fairy.glb`、`fairyStage.worker-*.js`。没有 GLB 会走同一骨架兜底；没有 `OffscreenCanvas` 会保留 CSS 光球。
- Lux3D 精灵生成失败：先跑 `npm run fairy:dry`；真实调用报 HTTP / c 错误时检查 Key、地区、积分（约 41）与 `--base-url`。旧网关 Key 可试 `--base-url https://api.aholo3d.cn`。任务状态 4/6 时看输出的 error；超时为 900s/步。
- 开始画面没出现真实珍宝：先确认 `public/models/manifest.json` 存在且路径对；DevTools Network 里应看到 `manifest.json`、GLB 与 `modelThumb.worker-*.js`。若 Worker 报错 / 浏览器不支持 `OffscreenCanvas`，会安静使用程序化图形，不影响开始页。
- 教学关不落快照：刷新会回到开始画面，这是设计（避免把教学进度混进正式存档）。
- 正式关刷新丢进度：检查 `localStorage['gemwright.run.v1']` 是否存在；若在但开始画面没「继续游戏」，看 `bootstrapState` 是否 `isActiveRunSnapshot` 通过。
- 卡在"集市布展"：看 Console 是否有 CORS / 401 / 积分不足；Lux3D 的 `Authorization` 不能加 `Bearer`；点「停止布展」可取消。
- 余额：DeepSeek 设置页「测试 Key」调 `/user/balance`；Lux3D 暂无余额接口，积分页自查。
- 预置模型没加载：先 `npm run models:dry` 确认路径，再看 `public/models/manifest.json` 是否存在；验货页底部会显示「本地预置模型 / 程序化占位模型」。
- Lux3D 报 `Failed to fetch`：先怀疑 Key / 地区 / 积分，而不是代码——Lux3D 的 401 / 400 等错误响应没有 `Access-Control-Allow-Origin`，浏览器读不到原因，只能给网络错误。国内统一用 `https://api.aholo.cn`，国际用 `https://api.aholo.ai/global`；`Authorization` 只放裸 Key，不加 `Bearer `。
- 区分“真跨域”和“被 CORS 掩盖的 401”：`curl -i` 同一端点，401 `invalid appKey` 是 Key/地区问题；200 但无 CORS 头才需要在部署平台加同源 serverless 代理。静态部署本身不会改变 API 的 CORS。
- 验货页报 `Failed to fetch dynamically imported module: .../viewer.ts`：这是 Vite 首次发现 three 依赖时"重新优化 → 整页刷新"打断动态 import 的竞态。已在 `vite.config.ts` 的 `optimizeDeps.include` 预打包 three 与 OrbitControls/GLTFLoader；若仍遇到，硬刷新（Cmd/Ctrl+Shift+R）并重启 `npm run dev`。生产环境不涉及该问题（viewer 是独立 chunk）。

## 10. 已知缺口（按优先级）

1. 真实 Key 未端到端联调；预置模型脚本与 Lux3D 精灵脚本（文生 3D / 绑骨 / 动画重定向）尚未用真实 Key 跑过（本轮无 Key），真实 GLB 的计数保真度与 humanoid 绑骨质量待核验。
2. 教学关暂不做刷新续玩（设计如此）；正式关已支持。
3. 演出仍可加：穿越文案分层、揭晓音效、结算奖章、摊主动画细节。
4. 整体移动端未专门适配（方案明确不做）；开始画面已单独做 390px 竖屏布局（手机最多加载 4 件预置模型），其余屏滑条与 3D 手势可用。
5. 真实模型加载性能未在 5×13MB 下压测；当前占位模型无压力。预置模型是按需单件加载，不阻塞首屏。
6. 精灵主路径是 Lux3D humanoid 带 skin 动画；程序化兜底仍是刚体骨绑。`OffscreenCanvas` 不可用时只显示 CSS 光球 + 台词，没有 3D 形象。
