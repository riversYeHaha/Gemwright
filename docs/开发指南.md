# 开发指南

> 配套《珍宝猎人》v8.1 方案（[方案全文](珍宝猎人-方案v8-MVP.md)）。这份文档只讲**代码怎么组织、改哪里、别踩什么坑**。

## 1. 环境与命令

```bash
npm install          # Node ≥ 22
npm run dev          # Vite dev server，http://127.0.0.1:5173
npm run typecheck    # tsc --noEmit（含 tests）
npm run lint         # ESLint flat config
npm run format       # Prettier 写回 src / tests / 配置
npm run test         # Vitest（happy-dom），15 files / 81 tests
npm run build        # typecheck + vite build → dist/
npm run verify       # typecheck + lint + format:check + test + build，提交前跑
npm run models       # 生成教学/演示预置 GLB（需 Lux3D Key）
npm run models:dry   # 只打印预置模型的 prompt / 输出路径
```

产物是纯静态站：`dist/` 直接丢任意静态托管即可，`vite.config.ts` 里 `base: './'` 保证相对路径。**不要**为了"跑起来"引后端——两个 AI 都由浏览器直连（CORS 已实测）。

## 2. 八个概念，记住就不会写乱

| 概念 | 代码位置 | 一句话 |
|---|---|---|
| `LevelJson` | `src/types/level.ts` | 一关的**权威数据**：世界、创作人、珍宝、价格。`kind` 区分 generated / demo / tutorial |
| `LevelSession` | `src/game/level.ts` | 一局的**唯一可变状态**：额度、报价、购买、精灵问答；`fromRuntime` 可恢复快照 |
| `AppState` | `src/app/store.ts` | UI 视图状态（当前屏、busy、提示、模型 blob、续玩/教学标记）。`store.set()` 触发整屏重绘 |
| 纯函数内核 | `validate` / `economy` / `bargain` / `fairy` | 不碰 DOM、不碰 store、可完全单测 |
| 适配层 | `src/api/*` | 只做 HTTP 与契约解析；游戏逻辑只依赖 `ChatClient` 接口 |
| **开始页** | `src/ui/screens/start.ts` | 无顶栏的落地页：继续 / 开始 / 教学 / 演示 / 设置 |
| **教学沙盒** | `src/game/tutorial/level.ts` | 预置两件珍宝 + 剧本问答 + 六步目标；不调模型、不写存档 |
| **预置模型** | `scripts/init_models.py`、`src/store/localModels.ts` | 脚本用玩家 Key 生成 GLB 到 `public/models/`（不入库）；网页按 manifest 加载，缺失回退占位 |

数据流：`actions.ts` 编排（生成 → 缓存 → 建 session → 改 store）→ `router.ts` 重绘 → 屏幕读 `session.state` 渲染。

## 3. 关卡协议与不变量

```ts
TreasureItem {
  name, pitch,
  traits:    真实可见特征（程序由 signatureTraits + tamperOps 推导）
  tamperOps: 混淆算子数组；[] ⇔ 真品
  isAuthentic: 程序覆写，LLM 说什么都不算
}
```

- **归一化入口**：`normalizeLevel(raw, {difficulty, funds, seedId, seedGenre, priceIndexRange, rng})`
  - Zod 校验失败 → 抛 `LevelSchemaError(issues)`，生成层把 issues 拼成"定向重试"提示。
  - 价格：`rebalancePrices` 强制 Σ ∈ [1.5, 2.2]×资金、单件 ≤ 0.9×资金、底价 ∈ [55%, 75%]。
  - 真伪：按难度目标真品数（3/2/1）增删仿品；仿品算子按难度整形（L1 两枚显性 / L2 一枚中等 / L3+ ±1）。
  - `trueValue` clamp 到创作人 `quoteRange`（普世锚，不乘物价指数）。
- **改数值**：只改 `src/config/constants.ts`；**改 prompt**：只改 `src/config/prompts.ts`。
- `renderPromptForTraits(traits)` 与判定共用 traits，改模板时保持"特征 ↔ 模型"一一对应。

## 4. 各模块职责与扩展点

### 世界种子（`game/seeds.ts`）
30 条 `{id, genre, priceIndexRange, mood}`。新增世界只需追加一条；`priceIndexRange` 会作为硬约束传给 LLM 并在归一化时 clamp。

### 生成（`game/generation.ts`）
- `generateLevel`：DeepSeek `jsonChat`（JSON mode）→ 归一化；最多 3 次，第 2/3 次把上次的 issues 回灌。
- `ensureLevelModels`：**并发**拉 5 件 GLB（免费档并发 5），先查 IndexedDB，成功即写回；单件失败只记录 `errors[itemId]`，不拖垮整关。
- 单件失败会自动重试 1 次，仅限 `Lux3DError.code` 为 `task-failed` / `timeout` 或网络类错误；鉴权、参数、积分不足不重试。
- `hooks.signal`（AbortSignal）贯穿 create / poll / download；取消后该件标记 `skipped`，不产生 error。

### 精灵（`game/fairy.ts`）
- `buildFairyContext(level)` **只能**取 world / creators 公开字段 / `collectTamperTypes`；**永远不要**把 `level.stalls` 传进去。
- `sanitizeQuestion`：≤50 码点；`filterAnswer`：压单行、截 100 字、命中"第X件 / T2 / 编号"整段替换为挡回语。
- UI 侧 `typewrite()` 做打字机；节点离屏（整屏重绘）后自动停表。

### 砍价（`game/bargain.ts`）
- `checkOffer`：结构闸门（已购 / 回合 / 额度 / 资金 / 非法报价）。
- 硬规则：`offer < bottomPrice` 必拒，**不问 LLM**。
- 混合模式：LLM 只输出 `{accept, line}`；失败退回 `localDecision`；兜底"接受价 ≥ 上次拒绝价"。
- 快速模式：设置页开关 → 全程 `localDecision`，零调用；教学关与演示关强制本地判定。

### 经济（`game/economy.ts`）
- 等级/额度：`levelForXp`、`offerQuota`、`fairyQuota`。
- 结算：`settleLevel(runtime, player, level, plan)`；`plan` 逐件 `{itemId, recycle}`，默认回收已购件。
- 结束：`checkMarketEnd` 顺序为 额度 → 资金低于最低底价 → 无可议之货；`actions.submitOffer` 在判定后自动收摊。

### 3D（`render/viewer.ts`）
- `new TreasureViewer(container)` → `show(blob | null, traits)`；有 blob 走 `GLTFLoader.parse`，否则按 traits 生成占位模型。
- 占位模型的星砂使用 `depthTest: false` + `renderOrder`，保证**所有颗数都可见可数**（教学关 7 vs 6 的判定基础）。
- 该模块由 `screens/inspect.ts` **动态 import**（独立 chunk）；离开验货屏由 `disposeInspectViewer()` 释放 WebGL，路由在每次重绘前调用。
- 异步加载用 `viewerToken` 防止快速切换时的竞态；`viewer-fog` 负责开箱雾，1.6s 后移除。

### 缓存与续玩（`store/cache.ts`）
- `gameCache.saveLevel / getLevel / saveModel / getModel / deleteLevel`。
- IndexedDB 不可用（隐私模式）自动退内存，本局仍可玩。
- `saveActiveRun / loadActiveRun / clearActiveRun`：localStorage 存整个运行时快照（关卡 JSON + `LevelRuntime` + 玩家），刷新续玩。
- 教学关**不写**快照（`persistActiveRun` 显式跳过）；退出教学时恢复教学前的玩家存档。
- 玩家存档 `gemwright.profile.v1`；教学关结算不写玩家存档（沙盒隔离）。

### 设置（`store/settings.ts`）
- 只存 `deepseekKey / lux3dKey / region / quickBargain / acknowledgedCreditCost`。
- 展示用 `maskKey`；不要新增"导出/上传 Key"的能力。

## 5. 预置 3D 模型（P0）

- **模型不入库**：`public/models/` 在 `.gitignore`；仓库只提交脚本与提示词。
- 脚本：`scripts/init_models.py`（Python 3.9+，仅标准库）。内置教学 2 件 + 演示 5 件的 traits，prompt 与 `src/config/prompts.ts` 的 `renderPromptForTraits` 保持一致。
- 用法：
  ```bash
  npm run models:dry                         # 预览
  export LUX3D_API_KEY=...
  npm run models                             # 默认国内端点，7 件 ≈ 91 积分
  python3 scripts/init_models.py --region global --force
  ```
- 输出：`public/models/{tutorial,demo}/*.glb` + `public/models/manifest.json`（`levels[levelId][itemId]` 存相对路径）。
- 加载：`store/localModels.ts` 用 `document.baseURI` 解析 manifest 与 GLB；内存缓存；manifest 缺失 / 404 / 解析失败一律返回 null。
- 回退：`actions.resolveModelsForLevel()` 先取 IndexedDB（正式关），再合并预置模型（教学 / 演示）；`null` 由 viewer 用 traits 占位模型。
- 加一件预置模型：在脚本的 `TUTORIAL_ITEMS` / `DEMO_ITEMS` 加 `PresetItem`，traits 与关卡数据保持一致，再跑 `npm run models -- --force`（或 `python3 ... --force`）。
- 校验：脚本 `--dry-run` 输出 JSON；真实生成需要 Key，生成后用浏览器看验货页底部是否标注「本地预置模型」。
- 成本：13 积分/件；已存在默认跳过，可反复执行；Key 只放请求头，不落盘、不打印。

## 6. 开始页与教学关卡

### 开始页（`ui/screens/start.ts`）
- 路由对 `start` 屏**不渲染顶栏**，落地页自带导航；其余屏用 `topbar()`。
- 主按钮优先级：有续玩快照 → 「继续上一局」；否则「开始游戏」。
- 「开始游戏」会丢弃续玩快照（新开一局）；想要保留上局就点「继续」。
- 无 DeepSeek Key 时额外给「演示关卡」入口；教学入口始终在。

### 教学关卡（`game/tutorial/level.ts`）
- `createTutorialLevel()` 手写世界 / 创作人 / 两件珍宝：真品 7 颗、仿品 6 颗，价格 380 / 350，能在 1000 资金内全买下且结算小赚。
- `TUTORIAL_QA`：5 条预设问答，其中 `which` 是**故意越界**的问题，返回 `BLOCKED_ANSWER`，用来演示防火墙。
- `tutorialObjectives({progress, askUsed, purchasedCount, phase, settled})`：六步全部由运行时状态推导，UI 用 `ui/tutorial.ts` 渲染；**不要**另埋事件。
- `tutorialObjectives` 依赖 `AppState.tutorial`：`{inspected: string[], openedMarket: boolean}`。`openInspect` / `beginShopping` 时更新。
- 教学关的 `persistActiveRun` / `persistPlayer` 都是 no-op；`startTutorial` 记录 `playerBeforeTutorial`，`goStart` / `nextLevel` 时恢复。
- 新增教学步骤：先在 `tutorialObjectives` 加目标，再在对应 action 里更新状态，最后补一条测试。

## 7. UI 约定

- 屏幕是**纯函数**：`renderXxx(state) → HTMLElement`；store 变化整屏重绘。
- 局部状态（输入框、滑条、对勾）藏在 DOM 里，动作触发时才读值；**不要**为每个按键 `store.set`（会丢焦点）。
- 新加按钮：`button(label, {variant, onClick, disabled})`；区块：`section(title, ...children)`；提示：`noticeBar(state.notice, dismissNotice)`；教学引导：`tutorialCoach(state)`。
- 样式分层：`tokens.css` → `base.css` → `components.css` → `screens.css` → `landing.css`。优先用 token，不要硬编码颜色。
- 重绘会销毁屏幕：需要清理的资源（WebGL、定时器）必须注册清理路径；打字机与 3D 加载都做了离屏/令牌保护。
- 开始页的视觉动效（宝石浮动、光环）在 `prefers-reduced-motion` 下自动关闭。

## 8. 测试策略

- 纯逻辑先测：`validate`（价格/真伪/难度）、`economy`（结算数学）、`bargain`（闸门/兜底）、`fairy`（防火墙/过滤）、适配层（请求头/状态码/重试）。
- 生成层用假 `ChatClient` / 假 `Lux3DClient`：喂坏 JSON 断言重试；`task-failed` 断言自动重试；AbortSignal 断言取消不出错。
- 会话与动作：`session.test` 覆盖额度/成交/结算；`actions.test` 覆盖教学六步、存档隔离、额度耗尽。
- UI 冒烟：开始页 / 设置 / 穿越 / 集市 / 基地用 happy-dom 渲染；`boot.test.ts` 真跑 `src/main.ts`，兜住循环依赖 / 首屏白屏。
- 新增玩法优先级：**先写不变量测试，再接 UI**。
- 预置模型：`tests/localModels.test.ts` 用假 fetch 覆盖 manifest / GLB / 缓存 / 404 / 网络异常；真实加载链路用合成 GLB 在浏览器验证过。
- 端到端（本机 Chrome + Playwright 驱动，非仓库依赖）：开始页 → 教学 → 精灵 → 验货 → 砍价 → 基地 → 结算 → 刷新续玩；截图存 `docs/screenshots/`。

## 9. 调试技巧

- DEV 模式浏览器控制台有 `window.gemwright`：
  ```js
  gemwright.store.get()               // 当前完整状态
  gemwright.store.get().session.state // 额度 / 报价 / 购买 / 阶段
  gemwright.actions.forceSeed(gemwright.store.get().nextSeed) // 固定当前种子
  gemwright.actions.startTutorial()   // 直接进教学
  ```
- 无 Key 想看 UI：开始页 → 教学关卡 / 演示关卡。
- 教学关不落快照：刷新会回到开始页，这是设计（避免把教学进度混进正式存档）。
- 正式关刷新丢进度：检查 `localStorage['gemwright.run.v1']` 是否存在；若在但开始页没「继续」，看 `bootstrapState` 是否 `isActiveRunSnapshot` 通过。
- 卡在"集市布展"：看 Console 是否有 CORS / 401 / 积分不足；Lux3D 的 `Authorization` 不能加 `Bearer`；点「停止布展」可取消。
- 余额：DeepSeek 设置页「测试 Key」调 `/user/balance`；Lux3D 暂无余额接口，积分页自查。
- 预置模型没加载：先 `npm run models:dry` 确认路径，再看 `public/models/manifest.json` 是否存在；验货页底部会显示「本地预置模型 / 程序化占位模型」。
- Lux3D 报 `Failed to fetch`：先怀疑 Key / 地区 / 积分，而不是代码——Lux3D 的 401 等错误响应没有 `Access-Control-Allow-Origin`，浏览器读不到原因，只能给网络错误。正确 Key + 地区 + 余额下成功响应才带 CORS 头。

## 10. 已知缺口（按优先级）

1. 真实 Key 未端到端联调；预置模型脚本尚未用真实 Lux3D 跑过（本轮无 Key），真实 GLB 的计数保真度待核验。
2. 教学关暂不做刷新续玩（设计如此）；正式关已支持。
3. 演出仍可加：穿越文案分层、揭晓音效、结算奖章、摊主动画细节。
4. 移动端未专门适配（方案明确不做，但滑条与 3D 手势可用）。
5. 真实模型加载性能未在 5×13MB 下压测；当前占位模型无压力。预置模型是按需单件加载，不阻塞首屏。

## 11. 提交与协作

- 分支：`main` 直推（黑客松节奏）；一次提交聚焦一件事。
- 提交信息：`feat: ...` / `fix: ...` / `docs: ...`，中文描述即可。
- 提交前：`npm run verify`；涉及 UI 改动附一张 `docs/screenshots/` 更新截图。
- 不要提交：`.env`、真实 Key、`.verify/`、`.npm-cache/`、`dist/`。
